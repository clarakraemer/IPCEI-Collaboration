# Replication bundle

Everything needed to reproduce the estimates, figures and tables in the paper.
Generated by `python -m ipcei_spillovers.publish`; it is rebuilt from scratch on
every run, so do not hand-edit anything here.

## Why the firm names are gone

The analysis rests on a LinkedIn-based dataset of collaboration announcements
(Toetzke et al. 2025) that we are not free to redistribute, and the working
panels identify firms directly: a LinkedIn slug per firm, plus website, URL,
city and coordinates in the firm-level files. Publishing them as they stand
would name every IPCEI recipient and every matched control alongside their
collaboration histories.

Every firm is therefore replaced by a stable pseudonym (`firm_0001`, ...). This
costs nothing analytically, because the estimation only ever uses the identifier
as a grouping key: `load_cs()` converts it to an integer `firm_id` on read.
Verified rather than assumed, running the primary specification on the original
and the published panel:

```
battery    ATT 0.291119803745 vs 0.291119803745 | SE 0.110405099632 vs 0.110405099632
hydrogen   ATT 0.162805142349 vs 0.162805142349 | SE 0.080004602448 vs 0.080004602448
```

Identical to every digit, bootstrap standard errors included.

The column is still called `Linkedin_name` rather than `firm_id`. That is
deliberate: `_cs_helpers.R` reads that column by name, so keeping it makes these
files a drop-in replacement for the authors' working directory. The values are
pseudonyms throughout, and `matched_to` is re-keyed to the same pseudonyms so
the matching structure survives.

## Contents

| Path | What it is |
|---|---|
| `panels/{tech}_psm_spec{1,2}_cs_ready.csv` | Firm-by-month panels, the direct input to the DiD. **Spec 1 is the primary specification**; spec 2 is the larger-control-group robustness arm. Outcome columns are all `n_collabs*`, monthly integer counts, which R log-transforms on read. |
| `panels/{tech}_psm_spec{1,2}_matched_firms.csv` | One row per firm: matching covariates (`log_staffCount`, `age`, `log_collab_count_2020`), the exact-matching strata (`nace1_psm`, `has_eu_operation`), the propensity score, and treatment flags. Enough to re-check balance and the match itself. |
| `results/` | Every R output: group-time ATTs, aggregated effects, event studies, pre-trend tests, power curves and diagnostics, namespaced by identification method (`psm`, `ebal`, `unmatched`). |
| `tables/main/`, `tables/si/` | The LaTeX exhibits exactly as they appear in the manuscript and supplement. |
| `tables/working-csvs/` | The aggregated descriptive CSVs behind the tables and figures. |
| `ipcei_approvals.csv` | The European Commission approval list that defines treatment and its timing. A public source, so firm names are retained here. |

## Not included

- The raw and interim LinkedIn data, which is third-party and not ours to
  redistribute.
- The entropy-balancing and unmatched-pool panels. Four files of 68 to 73 MB
  whose control pools are random 5,000-firm draws, so they would add 280 MB and
  disclose roughly 10,000 further firms without adding anything a replicator
  needs. The *estimates* from those arms are in `results/ebal/` and
  `results/unmatched/`.
- Firm-level descriptive CSVs that list named firms (top-10 collaborators,
  non-EU recipients, treated-control partner overlap pairs). Their aggregated
  counterparts are in `tables/working-csvs/`.
- The pseudonym crosswalk, which stays with the authors.
- Two result files that exist in our working tree but that we do not stand
  behind: the Rosenbaum sensitivity bounds, which are not valid under matching
  with replacement because matched sets overlap and were therefore dropped from
  the paper, and an extensive-margin table that is stale relative to the current
  outcome definitions.

## A note on what is in `results/`

`results/` is the full output tree, so it contains more than the paper reports.
`results/ebal/` is an entropy-balancing arm that is kept as a robustness reply
but not featured, because it fails the battery pre-trend test.
`consortium_size_att.csv` and the `honestdid_*` files are analyses we ran and
then deliberately did not use; the reasoning for each is in `CLAUDE.md` in the
code repository. Anything reported in the paper is in `tables/`.

## Reproducing the estimates

Point the R scripts in `R/markdown/` at `panels/` instead of `R/data/` and knit
them. The two numbers to check first are the technology-related ATTs in Table 1,
0.2911 for battery and 0.1628 for hydrogen.

Results come from `did` 2.3.0; other minor versions of that package can give
different numbers. Full environment in `../R/SESSION_INFO.txt`.
